# LLVM update — 2026-09-07

The default compiler is now LLVM **23.1.0**, selected by `llvm-release`
for local and CI builds. The release was published August 25, 2026. The
installed Clang reports commit `ea7d852a70e8bdfaf601d6626a760f9771b2c4b4`.
The official Linux X64 archive's published SHA-256 was verified:
`18da30f77f475688a18f7704d23f9f155ae007ed9922dbed6850a9419d9fec8c`.
See the [installation metadata](2026-09-07-install.json) and
[official release](https://github.com/llvm/llvm-project/releases/tag/llvmorg-23.1.0).

## Build behavior

`scripts/install_llvm.sh` resolves only the requested release. API errors,
wrong release responses, digest mismatches, and unusable tools fail the
build while preserving the previous installation. There is no fallback to
an unrelated release. Older explicit releases without published API
digests record the computed hash and mark it unverified.

The installer checks Clang, llc, llvm-config, llvm-strip and llvm-objcopy,
including the selected Clang/llvm-config version. The prebuilt linker
cannot run on this host because it requires ICU 70; the existing host
linker fallback selects `/usr/bin/ld.lld`. Both `LD` and `LLD` reach the
selftests Makefile, as fixed in the kernel advancement. A separate
[real host-helper build](2026-09-07-llvm-23.1.0-host-link-check.log) also
passed with LLVM 23 and GNU ld. See the [tool probe](2026-09-07-llvm-23.1.0-probe.json).

The default installation is `.build/llvm-install-23.1.0`.
`LLVM_RELEASE_TAG` and `LLVM_INSTALL` remain explicit overrides;
`--reuse-llvm` requires tools matching the selected release.
`--llvm-source` defaults to the same release tag, with `LLVM_BRANCH`
available for source experiments. The source path selects the requested
ref and rejects tracked edits before changing revisions. Source compilation
was not repeated for this update; the normal prebuilt path was built and
tested end to end.

Compiler identity includes actual tool hashes and archive provenance.
A changed identity rebuilds bpftool and selftests from fresh output
directories, including generated libarena objects in the source tree.
Previous outputs are archived for comparison. The successful local build
preserved LLVM 22.1.8 at `.build/llvm-install` and its outputs under
`.build/previous-llvm-artifacts.fZkEUx/`.
Installed and packaged version records describe the compiler actually
used, without taking a commit from an unrelated LLVM source checkout.

All four [installer failure tests](2026-09-07-installer-checks.log) pass:
API failure, wrong release, corrupt cached archive, and wrong compiler
version after extraction. Each verifies that the existing installation is
preserved. [Explicit reuse](2026-09-07-reuse.log) succeeds without replacing
the new compiler; [reusing LLVM 22 under the LLVM 23 pin](2026-09-07-reject-llvm22.log)
is rejected. CI runs the installer tests before packaging.

## Runtime comparison

The kernel base, patch program sources, GCC 13.3.0 and upstream pahole
`416753b4` match the LLVM 22 reference. The normal build also rebuilt the
kernel and modules; whole ELF files are not claimed to be identical.
The `bpf_testmod` machine-code `.text` hash remains
`0a88e42d4d94dee93589e99a5c6b09610dcd55a127bdf346c26e5b14084fc41e`.
The [version record](2026-09-07-version.txt) has trailing whitespace
trimmed; all values are unchanged from the installed manifest. The archived
gate log also trims trailing whitespace; the baseline JSON is byte-for-byte
unchanged from the measured summary.

The fresh [full sweep](../selftests-baseline/2026-09-07-1b7415bf7-llvm23-gate.json)
and [gate](2026-09-07-gate.log) pass: **629 OK / 58 FAIL / 80 SKIP /
0 NORESULT**, 31 chunks and zero host timeouts. All six changes are
SKIP to OK: `stack_arg`, `stack_arg_fail`, `stack_arg_precision`,
`verifier_aggregate_ret`, `verifier_stack_arg`, and
`verifier_stack_arg_order`. No pass is lost; every other recorded status
is identical. The [comparison](2026-09-07-comparison.json) preserves the
complete transition list. `CURRENT` adopts this measured result with no
new exclusions or flaky entries.

LLVM 23 defines `__BPF_FEATURE_STACK_ARGUMENT` and enables the real
stack-argument programs. The previously discussed four old dummy tests
had only changed their reporting to SKIP at the newer kernel pin; they
had not lost working coverage. They now execute and pass.

The [focused runtime check](2026-09-07-runtime.log) reports 8/65 passes,
one skip and zero failures for stack arguments, aggregate returns and
tracing, including all four tracing subtests. The [standalone corpus](2026-09-07-corpus.log)
passes with 991 inputs, 3,057 successful rows, 1,989 expected failure
rows, five expected processing failures and three expected open failures.
These rows include expected-rejection programs and are not runtime
regression counts.

The [exact arena check](2026-09-07-arena-confirmed.log) passes 67 program
expectations: 64 successes and three rejections. The sole addition is
`verifier_arena/check_arena_struct_ret`, guarded by Clang >= 23 in the
pinned source. It is absent from the preserved LLVM 22 ELF and present in
the new ELF. Only the manifest's program/success counts change; expected
rejections remain unchanged.

The local sweep used patched tree
`caece261c9f0756ed5432673a82671ae6bbe692e`. During that sweep, the preceding
pahole PR's CI exposed the independent [signing-key generation race](../pahole-update/2026-09-07-key-generation-race.md).
Its fix changes only the Makefile recipe and yields tree
`d2b1e0f1aa1a06362db2e87d44d5aa62408193c4`; it is included as this change's
parent. Parallel reproductions and the full Makefile check validate that
recipe separately. Remote builds validate the complete final stack.
