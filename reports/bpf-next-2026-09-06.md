## Coverage requiring a follow-up decision

Four previously successful dummy tests now skip with the local compiler:
`stack_arg_fail`, `stack_arg_precision`, `verifier_stack_arg`, and
`verifier_stack_arg_order`. Their upstream source already required
`__BPF_FEATURE_STACK_ARGUMENT` at the previous pin. The relevant upstream
change is adding `__skip` to the unsupported dummy programs which the
archived logs show were being run. The compiler requirements did not change
for UML/x86, and these four transitions are not lost working coverage.
The new `verifier_aggregate_ret` test explicitly requires LLVM 23.

The new `ksock_lsm`, `ksock_lsm_verifier`, and `sock_xattr` tests cannot
resolve `socket_bind`/`socket_sendmsg`/`socket_connect` LSM hooks because
`CONFIG_SECURITY_NETWORK` is disabled. The new `verifier_percpu_addr` test
fails with `fd 6 is not pointing to valid bpf_map`; its cause still needs
triage. These are new coverage gaps, separate from the five lost passes.

`tracing_struct` loses its previous pass because the new `int128_args`
subtest cannot find `bpf_testmod_test_int128_arg` in module BTF. The ELF
symbol exists. Re-encoding the same module object into separate diagnostic
BTF files shows that pahole 1.31's `consistent_func` filtering omits it;
without that filter, it is present. Neither the build flags nor installed
module BTF were changed in that initial experiment. Follow-up diagnosis
identified pahole's incorrect register expectations after a wide scalar
argument. A narrow candidate fix, keeping `consistent_func` enabled,
restores all four tracing subtests with the same GCC-built module code,
kernel, LLVM, and selftest binary. It is proven in a separate build and
subsequently integrated and validated in the normal build; see the
integration report above.
